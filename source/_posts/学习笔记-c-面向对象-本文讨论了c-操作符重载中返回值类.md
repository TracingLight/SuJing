在上一篇[操作符重载](/2026/08/04/学习笔记-c-面向对象-摘要-本文介绍了c-操作符重载的语/)说了一些基本内容，这时候我们马上会遇到一个实际设计问题：操作符的返回类型到底该写 void、值还是引用？如果写错了，连串操作（如 a = b = c）就会编译失败；如果返回了局部变量的引用，程序将出现悬空指针。

## 为什么不能全部返回 void？

如果操作符重载函数的返回类型是 `void`，则无法编写连串表达式，如 `a = b = c` 或 `cout << a << b`。编译器解析连串表达式时，需要前一步操作的结果作为后一步的输入，返回 void 会切断这个过程。

连串操作的本质

连串表达式 `a = b = c` 等价于 `a.operator=(b.operator=(c))`。内层 `operator=` 必须返回一个对象（或引用），外层才能继续调用 `operator=`。

## 返回引用有何好处？

返回引用（`return by reference`）不会产生临时对象拷贝，效率极高。对于大型对象（如 `std::string、std::vector`），每次值返回都会触发一次深拷贝，开销巨大。引用返回只需复制一个地址（通常为8字节），因此只要安全，优先返回引用。

> 易错点：返回引用时，必须确保引用的对象在函数返回后仍然存在。如果返回局部变量的引用，编译器可能不会报错，但运行时会出现悬空引用，导致不可预测的崩溃或数据损坏。这是 C++ 中最隐蔽的陷阱之一。

## 什么时候必须返回 value？

当函数返回的对象是局部对象（`Local Object`）时，必须使用 `return by value`。局部对象在函数结束时被销毁，任何指向它的引用或指针都会变成悬空引用（`dangling reference`）。安全高于效率，此时只能通过拷贝（或移动）返回一个新对象。

函数内部通过 Complex temp(...) 创建的对象，必须在返回时用值返回（return temp;），编译器会调用拷贝构造函数（或移动构造函数）生成临时对象。

![image](/img/posts/image-msecsn5k.png)

> 现代 C++ 编译器通常会对 `return temp;` 进行返回值优化（RVO）或命名返回值优化（NRVO），直接构造临时对象到调用方的存储位置，避免拷贝。因此，返回局部对象的值是安全的，且效率通常比想象中高。
>但 RVO 是优化，不是标准保证。如果代码依赖拷贝构造函数的副作用，建议显式返回 `std::move` 或依赖移动语义。总体而言，局部对象返回值是安全且现代的做法。
