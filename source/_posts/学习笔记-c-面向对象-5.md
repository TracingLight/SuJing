在前几篇中，我们学习了如何通过构造函数初始化对象，以及如何通过访问控制保护数据。然而，在我们实际设计类时，常常需要提供多种创建对象的方式，或者需要为同一个功能提供不同参数版本。这又又又引出了一个核心问题：C++ 如何允许同一个类中出现多个同名函数？又如何避免设计时的陷阱？

## 函数重载：编译器如何区分同名函数？

> 函数重载 Function Overloading
> 在同一作用域内，允许存在多个同名函数，这些函数必须具有不同的参数列表（参数个数不同或对应位置的参数类型不同）。返回类型不能作为区分依据。

设计目的：

提高代码可读性和易用性。例如，对一个复数类，可以定义两个 `real()` 函数——一个用于获取实部，一个用于设置实部。虽然名字相同，但参数列表不同，编译器可准确区分。

底层机制：

C++ 编译器通过 Name Mangling 将函数名与参数列表信息编码成一个内部唯一的符号名（如 `_Z3realRKCcomplex`），实现从程序员视角的“同名”到编译器视角的“异名”。

> 很多人误以为“同名函数”就是完全相同的函数名。实际上，C++ 中函数的“真实名称”包括参数列表信息。因此，重载本质上并不是“同名”，而是“同人眼所见之名，异编译器所见之名”。返回类型不同的两个函数不能重载，因为调用时编译器无法通过返回类型决定调用哪个版本（例如 `int f();` 和 `double f();` 一起调用 `f()` 会产生歧义）。

## 默认参数：简化调用的语法糖

> 默认参数 Default Arguments
> 允许在函数声明时为参数提供一个默认值。如果调用时没有提供该参数，编译器会自动使用默认值。语法：`void set(int real = 0, int imag = 0);`

要求：

- 默认参数必须从右向左连续指定（不能跳过中间参数设置默认值）。
- 默认参数通常在函数声明中提供，而不是在定义中，防止重复定义导致歧义。

作用：

增强函数的灵活性。一个带有默认参数的函数，可以变相地提供多个调用方式。例如，构造函数 `Complex(double r = 0, double i = 0)` 可同时支持无参、单参、双参三种调用方式。

## 冲突：无参构造函数与带默认参数构造函数的歧义

问题场景：

假设你写了一个复数类，已经有一个带两个默认参数的构造函数：`Complex(double r = 0, double i = 0);`。此时，如果你再定义一个无参构造函数 `Complex();`，那么当调用 `Complex c;` 时，编译器将无法确定该调用哪个构造函数，从而产生歧义错误。

正确做法：

只使用带默认参数的构造函数，不重复定义无参版本。一个构造函数即可覆盖所有场景。

```cpp
class Complex {
public:
    Complex(double r = 0, double i = 0) : real(r), imag(i) {}
private:
    double real, imag;
};
```


错误做法:

同时定义无参构造函数和带默认参数的构造函数，导致调用 `Complex c;` 时产生歧义。

```cpp
class Complex {
public:
    Complex();                    // 无参
    Complex(double r = 0, double i = 0); // 带默认参数
    // 调用 Complex c; 时，编译器无法区分
private:
    double real, imag;
};
```
