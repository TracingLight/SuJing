# 溯境项目工程指南

## 1. 目的与范围

本文是本仓库的程序工程说明，面向需要修改站点、管理内容、调整主题或维护 Cloudflare 服务的人。文档只描述当前仓库已经存在的实现；尚未实现的想法不能当作接口或部署前提。

当前项目是一个以 Hexo 生成静态 HTML 的个人博客，站点主域名为 `https://sujing.dev`。运行时交互由主题、`source/js/sujing.js` 和少量生成器脚本组成；文章、页面和 YAML 数据是构建输入，`public/` 是构建产物。

## 2. 技术基线

| 项目 | 当前值 | 来源 |
| --- | --- | --- |
| Node.js | `>=22 <25` | `package.json` 的 `engines` |
| npm | `10`（仓库声明 `npm@10.9.2`） | `package.json` |
| Hexo | `8.1.2` | `package.json` 的 `hexo.version` |
| 主题 | Butterfly `^5.5.5` | `package.json`、`_config.yml` |
| 时区 | `Asia/Shanghai` | `_config.yml`、`tools/hexo-tz.js` |
| 生成目录 | `public/` | `_config.yml` |
| 正式分支 | `main` | 发布脚本与 Cloudflare Pages 配置 |

Node 版本不满足范围时不要直接更新依赖来“修复”构建；先切换到支持的 Node 版本，再执行 `npm ci`。`package-lock.json` 是依赖安装的锁定来源。

## 3. 仓库结构与所有权

```text
SuJing/
├─ source/                    Hexo 输入：文章、页面、图片、音频、前端脚本和样式
│  ├─ _posts/                 文章 Markdown 与 Front Matter
│  ├─ _data/                  歌单、短讯、相册等 YAML 数据
│  ├─ img/                    已处理、会被站点引用的图片
│  ├─ media/music/            本地音乐文件
│  ├─ js/sujing.js            站点交互、统计、评论和 PJAX 后初始化
│  └─ css/sujing.css          站点自定义样式
├─ scripts/                   Hexo 生成器和渲染过滤器
├─ themes/                    主题层扩展（当前主题依赖来自 npm）
├─ tools/                     构建、发布、性能验收、本机控制台和图片上传工具
├─ infra/                     Cloudflare Workers、D1/KV/R2 配置与源码
├─ docs/                      工程和使用说明
├─ assets/user/               不直接发布的原始图片
├─ scaffolds/                 新文章、页面、草稿模板
├─ _config.yml                Hexo 基础配置
├─ _config.butterfly.yml      Butterfly 与站点外观配置
└─ public/                    Hexo 生成的部署产物，不是源文件
```

目录职责按“谁拥有它”判断：文章只在 `source/_posts/` 维护；构建逻辑放 `scripts/`；可从命令行执行的维护操作放 `tools/`；Worker 的运行时代码和绑定放 `infra/`。不要把生成后的 HTML 反向复制回 `source/`，也不要把原始图片直接当成站点资源引用。

## 4. 构建与请求数据流

```text
source/_posts + source/_data + _config*.yml
        │
        ├─ Hexo 8 / Butterfly
        ├─ scripts/site-data.js       → public/site-index.json
        ├─ scripts/responsive-images.js → public/img/responsive/*、_headers
        ├─ scripts/local-vendor.js    → public/vendor/*
        └─ scripts/site-redirects.js  → public/_redirects
        │
        └─ public/ → Cloudflare Pages

浏览器
  ├─ /site-index.json                 文章、分类、标签、歌单、短讯、相册和统计摘要
  ├─ stats.sujing.dev/v1/hit         访问统计 Worker
  └─ comments.sujing.dev/v1/comments 留言 Worker
```

`tools/hexo-tz.js` 是 Hexo 的统一入口，强制使用上海时区，避免本机、CI 和 Cloudflare 默认 UTC 导致文章日期、永久链接和管理台时间不一致。新增脚本调用 Hexo 时应保持这一入口，除非有明确的时区理由。

`site-index.json` 是前端首页、归档和部分 PJAX 逻辑共享的数据快照，不是内容源。修改文章或 `_data` 后必须重新构建，不能手工修改 `public/site-index.json`。

## 5. 内容与资源边界

### 5.1 文章

文章文件位于 `source/_posts/`，文件名是 slug 的主要来源。Front Matter 的常用字段如下：

| 字段 | 作用 |
| --- | --- |
| `title` | 标题 |
| `date` | 发布日期，影响排序和永久链接 |
| `updated` | 更新时间 |
| `categories` / `tags` | 分类与标签 |
| `description` | 摘要、首页卡片和 SEO 文本 |
| `cover` | `/img/...` 或 R2 的完整 URL |
| `cover_position` | 封面焦点，例如 `50% 35%` |
| `copyright` | 是否显示主题版权信息；默认保留 |

正文语法和 Butterfly 标签见 [写博客-Markdown语法.md](./写博客-Markdown语法.md)。首页、归档和前端脚本会读取文章的标题、日期、摘要、封面、分类和标签，因此改字段后要检查列表页和文章页，而不只是 Markdown 预览。

### 5.2 图片与音频

- `assets/user/` 保存原图，不会被 Hexo 发布。
- `source/img/user/` 保存已经筛选、裁切、压缩后的站点图片。
- 正文插图通常放 `source/img/posts/`，文章封面通常放 `source/img/covers/`。
- 本地音乐放 `source/media/music/`，歌单索引放 `source/_data/music.yml`。
- R2 上传使用 `npm run image:upload -- <file> [folder]`；生成的 URL 以 `image-host.config.json` 的 `publicBaseUrl` 为准。

不要覆盖原始素材，也不要把带密钥的本机配置、私密归档或测试文件放进 `source/`。管理台本地上传图片默认写入 `source/img/covers/`；勾选远程上传时先调用 R2，失败会回退为本地文件并返回警告。

## 6. 本机运行入口

安装依赖：

```powershell
npm ci
```

只启动博客预览：

```powershell
npm run server
```

直接运行 `npm run server` 时默认地址为 `http://localhost:4000`。需要内容管理、图片/音频上传和发布按钮时使用：

```powershell
npm run admin
```

`npm run admin` 会先启动 Hexo 预览，再启动绑定到 `127.0.0.1` 的本机 API，管理界面在博客右下角的“管”按钮中，不是独立站点。博客默认从 `4000` 开始，若被其它服务占用会自动顺延；已在运行且能识别为本站的预览会复用。API 默认从 `8787` 开始，端口冲突时最多顺延 12 次，也可以设置 `SUJING_ADMIN_PORT`。启动窗口会显示一次 Token，并把实际博客/API 地址写入被 `.gitignore` 排除的 `.sujing-admin.json`；前端通过 `/api/health` 读取 `blogHint`，不依赖固定的 `4000`。

本机管理 API 绑定回环地址，并仅给本地浏览器来源添加 CORS；除健康检查外的接口都要求 `X-Sujing-Admin-Token`。不要把 API 监听地址改成公网地址，也不要把 Token 写入文章、截图或提交记录。

## 7. 前端与管理 API 的职责

`source/js/sujing.js` 负责 PJAX 后重新挂载、首页/归档交互、音乐播放器、阅读进度、访问统计和留言展示。它调用两个公开 Worker 地址：

- `https://stats.sujing.dev/v1/hit`：按站点或文章路径记录访问数据。
- `https://comments.sujing.dev/v1/comments`：读取和提交留言。

本机管理 API 位于 `tools/admin/server.js`，其主要边界如下：

| API 组 | 数据来源或作用 |
| --- | --- |
| `/api/posts` | 读写 `source/_posts/*.md` |
| `/api/notes`、`/api/music`、`/api/gallery` | 读写 `source/_data/*.yml` |
| `/api/home`、`/api/about` | 读写首页和关于页 Markdown |
| `/api/upload/image` | 本地图片或 R2 上传 |
| `/api/upload/audio` | 写入 `source/media/music/`，上限 20 MB |
| `/api/actions/preview` | 启停本机 Hexo 预览 |
| `/api/actions/deploy` | 调用统一发布流程 |
| `/api/site-comments` | 使用本机评论管理员密钥代理 Worker 管理接口 |

新增管理功能时先确定唯一数据源，再补 API、前端和文档；不要让前端同时维护一份“缓存配置”。

## 8. 批注与专栏

### 8.1 文章批注

文章批注是 Markdown 正文中的 Hexo 标签，不使用数据库：

```markdown
{% annotation "批注内容" %}被解释的文字{% endannotation %}
```

`scripts/annotation.js` 在构建期把标签转成带无障碍属性的行内元素；`source/js/sujing.js` 负责点击、键盘、外部点击、Esc 和 PJAX 生命周期；`source/css/sujing.css` 负责桌面、移动端、深色模式及减弱动效。管理台只修改正文原文，因此 `/api/posts` 不需要新增接口。

### 8.2 专栏数据流

`source/_data/columns.yml` 是五个固定专栏的唯一配置源。`scripts/site-data.js` 读取文章分类和标签，对专栏名称做忽略大小写的精确匹配后，把文章摘要和专栏计数写入 `public/site-index.json`。主导航的“专栏”菜单以悬浮胶囊显示五个入口；`source/columns/index.md` 是专栏入口页，`scripts/columns.js` 为每个配置生成独立路由（如 `/columns/unity/`），`source/js/sujing.js` 在对应页面渲染文章卡片。一篇文章可以同时命中多个专栏，未命中专栏的文章不会被强行归类。

### 8.3 首页与导航

首页的“技术入口”模块已移除，“最新文章”占用完整桌面网格宽度；专栏入口由 `_config.butterfly.yml` 的主导航提供。修改首页结构时同步检查 `source/index.md`、`source/css/sujing.css` 和 `source/js/sujing.js` 的选择器。

## 9. 发布流程与不可逆操作

推荐发布入口是管理台“发布”页的“确认部署”按钮，或：

```powershell
npm run publish:site
```

发布脚本会按以下顺序执行：

1. 检查当前分支是 `main`，并 `fetch origin/main`；本地落后时停止。
2. `npm run check`：清理并重新生成 Hexo 产物。
3. `npm run prune`：移除不应上线的本机管理资源，并检查是否残留管理台引用。
4. `npm run check:performance-build`：验收最终 HTML、图片候选、缓存头和下线规则。
5. `git add -A`、提交全部未被忽略的修改，再推送 `main`。

GitHub 推送成功只表示源代码同步成功，不等于 Cloudflare Pages 部署成功。要在 Cloudflare Pages 查看对应部署记录；云端构建失败时修复后重新执行发布。脚本不执行强制推送或自动合并，推送失败会保留本地提交。

`npm run pages:deploy` 是手动直传 Pages 的备用入口，不会自动提交 Git。日常发布不要在两套入口之间交替使用，以免难以判断线上版本来源。

### 下线页面或资源

只删除 `source/` 文件不够：Cloudflare Pages 可能从历史部署回落同名路径。下线资源必须同时：

1. 删除源文件，使新产物不再包含它；
2. 在 `scripts/site-redirects.js` 的 `GONE` 数组登记路径，使 `public/_redirects` 返回 404。

完成后运行 `npm run check:performance-build`，确认 `_redirects` 已生成。

## 9. 验证矩阵

### 必做构建检查

```powershell
npm run check
npm run check:performance-build
```

性能构建检查会确认首页最新文章由构建期预渲染、首屏图片 eager、第三方依赖本地化、所有 `srcset` 候选存在且比原图小、`_headers` 有不可变缓存，以及 `_redirects` 包含 404 规则。

### 浏览器回归

需要验证交互或性能时：

```powershell
npm run server
node tools/prepare-performance-baseline.js
```

然后按 [性能优化与验收.md](./性能优化与验收.md) 的 Playwright 命令执行。至少覆盖桌面首页、文章页、归档、相册、音乐、关于页，以及 390×844 移动端。内容或前端脚本改动后应检查 PJAX 往返、音乐跨页播放、留言和统计请求是否重复。

### 发布前人工检查

1. 文章日期和永久链接是否正确，特别是北京时间午夜附近的新文章。
2. 封面、正文图片、音频在本地预览和构建产物中都能访问。
3. 文章摘要、分类、标签和封面焦点没有被管理台保存逻辑覆盖。
4. 删除资源时已同步 `site-redirects.js`。
5. `git status` 中没有 Token、私密配置、测试截图或 `public/` 之外的生成垃圾。

## 10. Cloudflare 服务与密钥

| 服务 | 配置文件 | 绑定/资源 | 部署命令 |
| --- | --- | --- | --- |
| 图片 Worker | `infra/image-host/wrangler.jsonc` | R2 `sujing-images` | `npm run image:deploy` |
| 统计 Worker | `infra/site-stats/wrangler.jsonc` | KV `STATS` | `npm run stats:deploy` |
| 评论 Worker | `infra/site-comments/wrangler.jsonc` | D1 `sujing-comments`、KV `RATE` | `npm run comments:deploy` |

Worker 管理密钥通过 Wrangler secret 或环境变量维护，不写入 `wrangler.jsonc`。本机评论管理台需要 `.sujing-comments-admin.json` 中的 Token，且必须与 Worker 的 `COMMENTS_ADMIN_TOKEN` 相同；这个文件已经被忽略。

图片公开地址在 `image-host.config.json` 中配置。第一次部署图片 Worker 后，如果 `publicBaseUrl` 仍是占位值，上传工具只会输出占位 URL，不会生成可用 Markdown。

## 11. 变更规则

- 构建输入、构建脚本和部署脚本必须一起考虑；修改 `source/` 后至少重跑一次构建验收。
- 修改 `_config.yml` 或 `_config.butterfly.yml` 后检查首页、文章页、归档、主题插件和导航，不要只看单个页面。
- 修改 `source/js/sujing.js` 时保留 PJAX 初始化的幂等性；事件绑定不能在每次软跳转后线性累积。
- 修改 Worker 的路由、CORS、限流或数据库结构时，先同步迁移文件和配置，再部署代码。
- 资源移动时保留引用关系；对于站点图片，源文件、`srcset` 生成和文章 Front Matter 必须同时核对。
- 说明当前行为时使用“已实现”；历史方案和未完成能力要显式标注，不能写成现行接口。

## 12. 已知边界

- `public/` 是可重建产物；不要在其中手工修线上问题。
- `npm run check:performance-build` 是产物结构验收，不替代真实用户的线上 INP、网络传输和 Cloudflare 部署验证。
- 评论和统计的本地浏览器检查应使用网络拦截或测试数据，不能向正式 Worker 写入测试留言和统计。
- 本机管理 API 和管理 Token 只适合单机维护，不提供多人协作或公网后台能力。
- R2 图片使用不可变缓存；同名内容更新应生成新文件名或新哈希 URL，不能依赖刷新缓存。
